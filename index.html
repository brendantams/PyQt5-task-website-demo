Build a custom button class

Subclassing QPushButton

inheritance __init__
⌄
Create a class StyledButton that extends QPushButton. It should accept label and color as constructor arguments, and set its own stylesheet automatically on creation — no styling code outside the class. 
from PyQt5.QtWidgets import QPushButton

class StyledButton(QPushButton):
    def __init__(self, label, color):
        super().__init__(label)
        self.setStyleSheet(f"background: {color}; border-radius: 6px; padding: 8px 16px;")

# Usage — the button styles itself:
btn = StyledButton("Submit", "#7b6ef6")

Hints

  • super().__init__(label) passes the text to QPushButton — always call this first
  • Because styling happens inside __init__, every instance styles itself automatically
  • Challenge: add a set_color() method so you can change the colour later

Make a reusable label + input widget

Composition with QWidget

composition self attributes
⌄
Build a class LabeledInput that wraps a QLabel and QLineEdit together in a vertical layout. Give it a method get_value() that returns the typed text. 
from PyQt5.QtWidgets import QWidget, QLabel, QLineEdit, QVBoxLayout

class LabeledInput(QWidget):
    def __init__(self, label_text):
        super().__init__()
        layout = QVBoxLayout(self)
        layout.addWidget(QLabel(label_text))
        self.input = QLineEdit()
        layout.addWidget(self.input)

    def get_value(self):
        return self.input.text()

# Usage:
name_field = LabeledInput("Patient name")
print(name_field.get_value())

Hints

  • Inherit from QWidget, not from QLineEdit — the class has a widget, it doesn't become one
  • Storing the input as self.input means get_value() can reach it
  • Challenge: add a set_placeholder(text) method that sets placeholder text on the input

A screen base class

Abstract patterns and shared behaviour

base class method overriding
⌄
Create a BaseScreen class with a shared title label and a setup_ui() method that does nothing. Then make two screens — HomeScreen and ResultScreen — that each override setup_ui() to add their own content. 
from PyQt5.QtWidgets import QWidget, QLabel, QPushButton, QVBoxLayout

class BaseScreen(QWidget):
    def __init__(self, title):
        super().__init__()
        self.layout = QVBoxLayout(self)
        self.layout.addWidget(QLabel(title))
        self.setup_ui()  # each subclass fills this in

    def setup_ui(self):
        pass  # subclasses override this

class HomeScreen(BaseScreen):
    def setup_ui(self):
        self.layout.addWidget(QPushButton("Start screening"))

class ResultScreen(BaseScreen):
    def setup_ui(self):
        self.layout.addWidget(QLabel("Results will appear here"))

Hints

  • BaseScreen.__init__ calls self.setup_ui() — so subclass content gets added automatically
  • This is the exact pattern behind a QStackedWidget multi-screen app
  • Challenge: add a go_back() method to BaseScreen that prints "go back" — override it in one subclass

Yes/No question widget

Encapsulation and state

encapsulation instance state
⌄
Build a YesNoQuestion widget that takes a question string, shows two buttons (Yes / No), and tracks which was selected internally. Add a method get_answer() that returns True, False, or None. 
from PyQt5.QtWidgets import QWidget, QLabel, QPushButton, QHBoxLayout, QVBoxLayout

class YesNoQuestion(QWidget):
    def __init__(self, question):
        super().__init__()
        self._answer = None  # internal state
        layout = QVBoxLayout(self)
        layout.addWidget(QLabel(question))
        btns = QHBoxLayout()
        yes = QPushButton("Yes")
        no  = QPushButton("No")
        yes.clicked.connect(lambda: self._set(True))
        no.clicked.connect(lambda: self._set(False))
        btns.addWidget(yes)
        btns.addWidget(no)
        layout.addLayout(btns)

    def _set(self, value):
        self._answer = value

    def get_answer(self):
        return self._answer

Hints

  • The underscore in _answer signals it's internal — nothing outside the class should set it directly
  • lambda: self._set(True) is a common pattern for connecting buttons with arguments
  • Challenge: visually highlight the selected button (e.g. bold text) when clicked

Mini form that collects itself

Putting it all together

composition inheritance encapsulation
⌄
Build a PatientForm screen using your classes from tasks 1–4. It should contain two LabeledInput widgets (name, location) and one YesNoQuestion. Add a get_data() method that returns a dict with all three values. Wire up a StyledButton that prints the result. 
class PatientForm(BaseScreen):
    def setup_ui(self):
        self.name     = LabeledInput("Name")
        self.location = LabeledInput("Location")
        self.fever    = YesNoQuestion("Do you have a fever?")
        submit        = StyledButton("Submit", "#7b6ef6")
        submit.clicked.connect(lambda: print(self.get_data()))

        for w in [self.name, self.location, self.fever, submit]:
            self.layout.addWidget(w)

    def get_data(self):
        return {
            "name":     self.name.get_value(),
            "location": self.location.get_value(),
            "fever":    self.fever.get_answer(),
        }

Hints

  • Each component manages its own state — PatientForm just calls their methods to read it
  • This is how your NTD symptom questionnaire works — each question is a self-contained object
  • Challenge: add validation — only print data if name isn't empty and an answer was selected
